> 範圍：自評題 selfcheck 題型、國語一百分卷版型、一課題庫 schema。
> 本文件不含任何實際課文內容或課名；所有題數、配分皆為「提案」，不是任何學校的實際版型，待使用者定案。

## 1. 引擎現況摘要（與國語相關的擴充點）

### 1.1 題型與資料契約（現行）
- 題型由各科 `config.types` 注入，引擎本身只認 `kind`/`key`：`single`（單選）、`multi`（複選）、`tf`（是非）、其餘一律走「文字作答」分支（`fill`/`calc`/`word`）。
- 題庫 spec：`{id, type, level 1~5, tag basic|trap|extend, gen(kit)}`；`gen` 回傳 `{stem, explain(必填), options/answer, accepted, units, trapNote, explain2}`。引擎 `validateRaw()`（engine.js 約 116 行）檢查：stem、explain 非空；single/multi 要 options 與合法 answer；tf 要布林；其餘要求 `answer` 非空字串。
- `realize()`（約 132 行）呼叫 gen、洗牌選項、重算答案；文字題 `answer/accepted/units` 轉字串。
- 國語現有 `factory.js` 只會產 `single/multi/tf/fill`，沒有組卷以外的特殊邏輯。

### 1.2 一百分卷組卷
- `buildExam()` → `planScore(keys)`（約 278 行）：用動態規劃找「題數 × 每題分」使總分剛好 100，成本函數貼近各型的 `stdCount/stdPts`；有 `minCount/maxCount/minPts/maxPts` 硬限制，無解才逐級放寬。
- 重要發現：**全選題型時，若各型 `stdCount × stdPts` 加總恰為 100 且落在範圍內，planScore 的成本為 0，會精準回到標準版型**（數學頁就是這樣得到 5/10/12/3/4 題的標準卷）。所以國語標準版型「不必改引擎」，只要 config 的 `stdCount/stdPts` 設對。只勾部分題型時會按比例重分配（同數學規則）。
- 大題順序＝`config.types` 陣列順序；大題標題由 UI 組成「一、題型名（每題 X 分，共 Y 分）」，說明句取自 `type.hint`；`stdWith` 可在與某型同時勾選時換成另一組標準（數學的複選借單選分數即此用法）。
- `selectSpecs()`（約 224 行）：依單元均衡、trap/extend 標籤比例、難度涵蓋選題；去重只以 spec.id 為單位，**同一題型內**不重複；**跨題型不去重**（國字注音與注音寫國字若用同一個字詞，會互相洩題，需處理，見 4.5）。
- 題內排序 `stableSortByLevel()`：先洗牌再依 level 排序（由簡入深）。這會把同一篇閱讀的子題拆散，見 3.4。

### 1.3 UI／列印／答案卷（ui.js、exam.css）
- `itemCard()`（約 277 行）：以 `it.type` 分支畫 single/multi、tf，其餘都落入「文字輸入框＋列印橫線」分支。題幹用 `textContent` 顯示（**不能放 HTML／ruby**），CSS `.ex-stem` 為 `pre-wrap`，換行可用。
- 列印：`@media print` 隱藏輸入框／按鈕，文字題顯示 `.ex-printline`，計算類顯示 `.ex-printlines`（多行橫線）。「列印答案卷」靠 `body.ex-print-key`。
- 答案卷 `keyCard()/answerSheet()` 用考卷實際那份 `explain/explain2`，不重新 gen。
- 結果頁 `renderResult()` 呼叫 `engine.summarize()`：總分、各大題得分、標籤／單元統計、錯題檢討。
- 計分假設：每題答對 `earned=points`，否則 0；`isAnswered/isCorrect` 對未知 type 一律當文字題。

### 1.4 與國語相關的擴充點（彙整）
1. config 層（零引擎改動）：新增國語題型 key、`stdCount/stdPts`、`hint`、`normalizeText`（注音、錯字答案正規化）。
2. 新題型 `selfcheck`：需動 engine.js 與 ui.js（第 2 節）。
3. 閱讀短文「一篇多題」共用短文：需動 engine 的排序與 UI（3.4）；也可先用「每題內嵌短文」的零改動作法過渡。
4. 跨題型去重（國字注音 vs 注音寫國字）：資料層可解（4.5），引擎層為選配。
5. 注音符號顯示／輸入：純 config＋CSS 層，但需實機測字型（第 5 節風險）。

## 2. 新增「自評題 selfcheck」設計

### 2.1 定位
給「無法由程式批改的開放作答」（先用在造句，日後可用於短文改寫、心得句）。學生自己寫、自己對照評分標準勾選。**預設不併入自動批改的對錯統計**；是否計入一百分卷的分數，由 3 節方案決定。

### 2.2 資料欄位（spec.gen 回傳）
```
type: "selfcheck"           // spec.type 與 config.types[].key、kind 皆為 "selfcheck"
stem:     "題目指示文字（例：請用下列語詞各造一個句子）"
keywords: ["語詞1"]          // 要求語詞，1~2 個，必填（可為空陣列代表不限）
sample:   "參考範例句（原創，一至兩句）"   // 必填；答案卷與自評區顯示
sampleNote: "選填：這個範例為何合格"
rubric:   ["項目1","項目2","項目3","項目4"]   // 評分標準，3~5 條，每條一句、可勾選
explain:  "寫作提醒／常見錯誤（必填，沿用引擎對 explain 的要求）"
trapNote: 選填
```
- 配分：該題 `points` 由大題決定；引擎在組卷時用既有 `apportion(points, 等權重)` 把分數均分到每條 rubric（無法整除時前幾條多 1 分），存成 `item.rubricPts[]`。
- 預設評分標準（config 提供通用 4 條，spec 可覆寫）：①用到指定語詞且用法正確；②句子完整、通順（有主詞與動詞，意思清楚）；③標點符號正確；④句子不是只換一兩字抄範例／內容具體。
- `answer` 欄位：引擎在 `validateRaw` 對 selfcheck 允許不提供，由 `sample` 代入，使 `describeAnswer()` 可沿用。

### 2.3 UI 行為
- **作答時**：顯示題幹、要求語詞（醒目 chip）、一個多行輸入框（`textarea.ex-selfwrite`，內容只留在畫面，供孩子自己看，不判分）。可提供「看參考範例」折疊鈕（預設收合，避免先看答案；寫完才展開）。
- **交卷後（結果頁）**：新增「造句自評」區，每題一張卡：顯示題目、孩子寫的句子、參考範例、rubric 勾選框；勾選即時更新該題得分與大題小計、總分旁的「自評分」。未勾者不給分。孩子沒寫句子時，勾選框 disabled 並提示「未作答」。
- 勾選結果存在 `state.self[no] = [true,false,…]`，可選擇一併存入既有 localStorage 鍵（目前只存設定，不存作答；建議維持不存作答，與數學一致）。
- 進度列「已作答 N／M 題」：**排除 selfcheck**（避免未造句卻阻擋交卷警告）；交卷警告文字改為「還有 X 題沒作答；造句為自評題不影響交卷」。
- 逐題練習模式（20 題）：selfcheck 預設不出現（見風險）；若要出現，「檢查」鈕改為「看範例與評分標準」，不判對錯。

### 2.4 列印行為
- 考卷：題幹＋語詞＋3～4 行 `.ex-printlines` 橫線；`textarea` 在 print 隱藏（比照 `.ex-work`）。
- 答案卷：列出參考範例＋評分標準（每條附配分，方便家長在紙本上勾）；`@media print` 內 `.ex-rubric` 以空心方框 ☐ 呈現。
- 結果頁列印：勾選狀態以 ☑/☐ 文字呈現，不依賴表單元件顏色。

### 2.5 一百分卷如何配分與合計顯示
- 由大題屬性控制，不寫死：`type.scoring`：`"auto"`（現行）／`"self"`（自評計入）／`"none"`（不計分）。
  - `self`：納入 `planScore`，與其他大題一起湊滿 100；總分＝自動批改分＋自評分。結果頁**分開顯示兩個小計**：「自動批改 X／Y 分」「自評 Z／W 分」，總分框標「合計 X+Z／100」，並加註「自評分由你自己對照標準勾選」。
  - `none`：不進 `planScore`（100 分由其他大題分完）；大題標題改為「附加：造句自評（每題 X 分練習用，不計入 100 分）」，結果頁另列「自評練習 Z／W」。
- 交卷時未自評＝先以 0 分合計，結果頁頂端提示「造句尚未自評，目前合計不含造句」。

### 2.6 對引擎的最小改動清單（檔案＋函式層級）
**engine.js**
1. `validateRaw`：新增 `selfcheck` 分支（檢 `sample`、`rubric` 3~5 條字串、`keywords` 陣列）。
2. `realize`：selfcheck 分支複製 `keywords/sample/sampleNote/rubric`，`answer=sample`。
3. `buildExam`：把 `scoring==="none"` 的題型從 `planScore` 的 `keys` 移出，另用 `type.stdCount` 補入 `counts`；`scoring==="self"` 照常參與 planScore。
4. `assemble`：selfcheck 的大題標記 `section.self=true`、`section.counted=(scoring!=="none")`；`total` 只加 counted 的大題；為每題算 `rubricPts`（呼叫既有 `apportion`）。
5. `isAnswered`／`isCorrect`／`gradeItem`：selfcheck 一律「不參與對錯」（`isAnswered` 回 true 或另行排除；`gradeItem` 回 `{self:true, earned:0}`，由 UI 傳入勾選結果才算分）。
6. `summarize(exam, responses, selfMarks)`：新增第三個參數（預設 `{}`，**舊呼叫完全相容**）；selfcheck 不進 `wrong`／`byTag`／`byType`／`byUnit`；`score` 拆成 `autoScore`、`selfScore`，`score=autoScore+(counted?selfScore:0)`；`bySection` 增加 `self:true` 旗標。
7. `describeAnswer`／`describeResponse`：selfcheck 回傳 sample／孩子寫的句子。
8. `rebuildFromItems`（只重做錯題）：已排除 selfcheck 即可（它不在 `wrong`）。
**ui.js**
9. `itemCard`：在文字分支前加 `selfcheck` 分支（chip＋textarea＋折疊範例）。
10. `renderExam`：大題標題對 `section.self` 用自評文案；`answeredCount`／交卷警告排除 selfcheck。
11. `keyCard`／`answerSheet`：selfcheck 顯示範例與 rubric；標題文案同上。
12. `renderResult`：新增自評區與即時重算（勾選時重算 `sum` 並更新 `#ex-score`、各大題列）。
**exam.css**
13. 新增 `.ex-selfwrite`、`.ex-kw`（語詞 chip）、`.ex-rubric`、列印規則（隱藏 textarea、顯示橫線與 ☐）。
**config（國語）**
14. `types` 加 `{key:"sentence", kind:"selfcheck", scoring:"self"|"none", stdCount, stdPts, rubricDefault:[…]}`。

### 2.7 風險與回歸測試（數學頁不能壞）
**風險**
- R1：改 `summarize` 簽名／回傳結構可能影響現有呼叫端（ui.js 結果頁、各科 verify 腳本）。對策：新參數預設值、新欄位只增不改，既有欄位語意不變。
- R2：`planScore` 的 keys 過濾若寫錯，會改變數學配分。對策：只在 `scoring==="none"` 才過濾，數學 config 沒有此欄位。
- R3：自評分數不是客觀成績，家長可能誤讀。對策：分開小計＋標示「自評」。
- R4：孩子可能不勾或亂勾。對策：預設 0 分、方案甲才計入；方案乙不計。
- R5：`isAnswered` 語意被改，導致「全部作答」判斷錯。對策：UI 層排除 selfcheck，不改文字題判斷。
- R6：逐題練習模式含 selfcheck 時「檢查」無對錯，易混亂。對策：練習模式預設濾掉 selfcheck。
**回歸測試**
1. 快照比對：在改動前先對數學／國語（舊）／英語（若使用同引擎）跑 `planScore` 的全部題型子集（63 種組合）輸出 JSON，改動後逐筆全等（planScore 為決定性函式）。
2. 既有腳本全跑：`grade6-math/verify-engine.js`、`verify-banks.js`、`verify-explain.js`、`verify-notation.js`、`verify-numbers.js`；國語 `verify-banks.js`、`verify-notation.js`。
3. `summarize` 對舊考卷物件（無 selfcheck）輸出與改動前的欄位逐值相同（固定 responses 做 golden test）。
4. 瀏覽器實測（桌機＋390px）：數學頁一百分卷與 20 題、交卷、錯題重做、顯示答案卷、列印預覽；console 0 error。
5. 新增 selfcheck 單元測試：validateRaw 拒收缺欄位；rubric 配分加總＝題分；`counted` 兩種情境總分正確；未自評總分提示。
6. 英語頁（`sixth-grade-english`）若用同引擎，同樣開頁無錯誤。

### 3.4 閱讀短文「一篇多題」的處理（兩階段）
- 階段 0（零引擎改動，樣板先用）：每個子題 stem 內嵌同一篇短文？不建議，同篇會重複印 5 次，版面浪費。
- 階段 1（建議）：新增「題組 spec」：`gen` 回傳 `{passage, questions:[{stem,options,answer,explain}…固定 5 題]}`；`realize` 展開成 5 個 item，帶 `passage`、`setId`；`assemble` 保持同組相鄰、跳過 `stableSortByLevel` 對組內的洗牌；UI 在同一 `setId` 的第一題上方印短文一次，列印時短文不被分頁切斷。`reading` 的 `count` 以「篇」計（`stdCount:1`），每題配分由 `stdPts` 給。
- 引擎改動點：`validateRaw`（題組分支）、`realize`/`realizeAll`（展開）、`assemble`（組內排序與題號）、`planScore`（題數＝篇數×每篇題數）、ui.js `itemCard`/`renderExam`（短文區塊）、`answerSheet`（短文只印一次）。屬中等改動，需另走完整回歸測試。

## 4. 「一課」題庫 schema 草案

### 4.1 單元與 topic 對應
- 一課＝一個單元＝一個 topic（`topic id` 建議 `kx-6a-01` 形式：出版社縮寫-冊-課序；實際編號待課次清單查證後定）。`config.versions.kanghsuan.units` 每課一筆：`{unitId:"六上-3", semester, title:<課名，需有來源>, topics:["kx-6a-03"], verified:true|false}`。
- 檔案：`banks/bank-<topic>.js`；引擎載入機制（index.html 依 `allTopics` 逐檔載入、缺檔略過）不變。`unitAvailable()` 以「該 topic 是否有 spec」決定單元可選，題庫沒做的課不會出現可選項。

### 4.2 一課資料檔結構（由新 factory 轉成 spec）
```
LessonBank.register("kx-6a-xx", {
  meta: {
    lessonNo, semester, title, genre, author,
    sources: [{ field, kind:"publisher-catalog|moe-dict|user-provided|public-web", url|note, checkedAt }]
  },
  newChars:  [{ char, zhuyin, source }],          // 生字（僅公開查證或使用者提供）
  newWords:  [{ word, zhuyin, meaning, source }], // 語詞
  zhuyin:    [{ word, target, zhuyin, accepted:[], note }],   // 看國字寫注音，target＝被問的字
  hanzi:     [{ context, zhuyin, answer, accepted:[] }],       // 注音寫國字，context 必須讓答案唯一
  homophone: [{ stem, correct, wrongs:[3 個，非同音], explain }],
  wrongchar: [{ sentence, wrong, right, explain }],            // 句中含一個錯字
  vocab:     [{ stem, answer, accepted:[], hint, explain }],   // 語詞填空
  lessonmc:  [{ stem, correct, wrongs:[3], factKind:"title|genre|author|word-meaning|char", explain, source }],
  reading:   [{ setId, origin:"original", passage, questions:[{stem,options,answer,explain}×5] }],
  sentence:  [{ keywords:[…], sample, rubric?:[…], explain }]
})
```
- 每個條目都對應一個 spec，id 規則沿用 `topic-type-Lx-nn`，`factKey` 必填（同 topic 不重複，沿用現行 verify 規則）。
- 難度 level／tag 先由資料檔明列，不再用 `factory.js` 依序號自動分配（現行 `meta()` 以陣列序號決定 trap/extend，對國語字詞不適用）。

### 4.3 題數門檻建議（每課，單課出卷也要湊得出一張卷）
| 題型 | 每課最少 spec | 說明 |
|---|---|---|
| zhuyin | 12 | 單課出卷需 10 題且保留換題空間 |
| hanzi | 12 | 與 zhuyin 的字詞要分開池（4.5） |
| homophone | 8 | 需 5 題 |
| wrongchar | 8 | 需 5 題 |
| vocab | 12 | 需 10 題 |
| lessonmc | 12 | 需 10 題；只限可查證事實，故來源不足時可降為「待補」 |
| reading（題組） | 2 篇（各 5 題） | 自編原創；單課出卷抽 1 篇 |
| sentence | 4 | 需 2 題，語詞不同 |
- 難度：每型至少涵蓋 2 個 level；整課 trap（易混字、破音、形近字）≥ 6、extend ≥ 4。字詞量不足的課可降低門檻，但要在 `meta` 註記並由使用者同意。
- 變化方式：國語沒有數字變數，變化來自「抽哪個字詞」「干擾項抽取與洗牌」「同題多種題幹句型」；故門檻以「可抽候選數」為主。

### 4.4 資料來源規則（硬規則）
1. 課文是出版社著作：**禁止憑記憶複製、改寫、摘要課文內容出題**；課文內容題只能使用使用者提供的文字／照片，並在資料標 `source.kind:"user-provided"`。
2. 可公開查證才可寫入的欄位：課名、冊次課序、文體、作者、公開的生字語詞表；每筆須有 `source`（URL 或使用者提供）。查不到＝該欄位留空、相關題型不出（lessonmc 以「不確定的不出」處理）。
3. 注音與字形、同音字、形近字：以教育部重編國語辭典為準，逐筆對照；一字多音需註記語境。
4. 閱讀短文：完全自編原創（`origin:"original"`）；不得套用既有課文、報章、他人文章的句子；不仿寫課文情節；內容避免與特定課文相同題材的細節。
5. 造句範例：自編原創，不取自課本習作。
6. 不確定的不出；寧可題少也不放未驗證題目（`verified:false` 的課維持 beta 標示，與現行頁面做法一致）。
7. 驗收：新增 `verify-lessons.js`（欄位完整、id 規則、來源欄位非空、注音符號合法字集、單答案唯一性、題數門檻、簡體詞掃描）；事實由 fresh-reviewer 另行對照辭典與公開資料，不由出題者自驗。

### 4.5 跨題型洩題處理
- 資料層（建議先用）：`newWords` 每筆標 `use:["zhuyin"|"hanzi"|"vocab"]`，同一個字詞只分配給一種題型。
- 引擎層（選配）：`selectOnce` 增加以 `factKey` 跨題型去重（`usedFacts`）。

## 5. 開放問題（需使用者決定）

1. **課次清單來源**：康軒六上、六下課名與課序，請提供目錄頁照片，或授權我們查公開來源；在此之前不可定 topic id 與課名。
2. **學校實際考卷樣本**：能否提供孩子學校一份真實國語段考卷（照片）？用來校正大題順序、題數、配分，現有版型只是通則提案。
3. **造句計分**：方案甲（自評計入 100 分）或方案乙（不計分、附加練習）？
4. **自評時機**：勾評分標準放在「交卷後結果頁」（建議，避免先看答案）還是作答中即可勾？
5. **國字注音的輸入方式**：孩子在裝置上要打注音符號（含聲調）嗎？選項：(a) 文字輸入並放寬等價寫法；(b) 改為「看標準注音後自評對錯」；(c) 改成選擇題。選 (a) 時第一聲不標調、輕聲「˙」位置等寫法規則要訂。
6. **課文相關選擇題的材料**：除課名／文體／作者／生字語詞外，是否由使用者提供每課重點（大意、習作）？不提供則此大題內容會很窄，可能改以更多語詞辨析題替代。
7. **閱讀短文**：每卷一篇五題是否足夠？是否需要兩篇（一記敘、一說明）？短文字數（建議 300～450 字）與主題範圍要不要先給方向？
8. **多課合卷**：預設是「勾一課出一課卷」還是「可複選多課（期中範圍）」？樣板先做單課，之後合卷是否要補跨課題量？
9. **注音顯示**：現行 UI 以純文字顯示，無法做「注音在字旁」的 ruby 排版與底線標記目標字；樣板先用括號／「」標示可以嗎？若需要正式版面，要追加引擎「題幹 HTML 片段」改動（有 XSS 防護成本）。
10. **逐題練習模式**（20 題）：是否收國語新題型？造句是否在練習模式出現（預設建議不出）？
11. **一課樣板選哪一課**：待課次清單確認後，由使用者指定；建議挑生字詞量中等、有公開生字語詞表的一課。
12. **引擎改動授權**：自評題＋題組展開需要動共用引擎 engine.js/ui.js/exam.css，是否同意在完成回歸快照（2.7）後才動？
