# 題型多元高質量動態變數互動考卷系統｜規格（2026-10-11 使用者定案）

目標：取代國小六年級數學舊的「小節 10 題」練習頁，做成可複製到國語／社會／自然的通用考卷引擎。**先只做數學，使用者確認後才複製到其他科目。**
不使用任何後端、框架或 CDN（舊頁用 Tailwind CDN，新頁禁用；樣式寫在 `exam-engine/exam.css`）。純靜態、可離線（PWA）。

## 2. 題型（六種）與資料契約

題型 key：`single` 單選、`multi` 複選（選擇）、`fill` 填空、`tf` 是非、`calc` 算式題、`word` 應用題。

標籤 `tag`：`basic` 基礎、`trap` 易錯陷阱、`extend` 深入延伸。難度 `level` 1～5（1 最易）。

題庫檔格式（每檔一個 topic，IIFE 末尾註冊）：

```js
ExamBank.register("factor", "gcd-lcm-basic", [ // topic, 檔內群組名（僅供除錯）
  {
    id: "factor-single-L1-01",      // 全域唯一、穩定（用於錯題統計）
    type: "single",                 // 六種之一
    level: 1,                       // 1~5
    tag: "basic",                   // basic | trap | extend
    gen(kit) {                      // 每次呼叫產生新變數；必須無副作用
      // 回傳：
      return {
        stem: "題幹文字（純文字，可含換行；數學式用 a/b、×、÷、²）",
        options: ["…","…","…","…"], // single/multi 必填（single 4 個、multi 4~5 個）；tf 不填
        answer: 0,                  // single=正解索引；multi=索引陣列（升冪）；tf=true/false；fill/calc/word=字串（標準答案）
        accepted: ["3/4","0.75"],   // fill/calc/word 選填：其他等價寫法
        units: ["公分","平方公分"],  // fill/calc/word 選填：可接受的單位後綴（引擎批改時去除）
        explain: "解析：逐步算式（必填，至少一個完整算式或理由）",
        trapNote: "易錯點說明（tag=trap 必填：說明學生常錯在哪、錯誤做法會得到什麼）"
      };
    }
  }
]);
```

規則：
- `single`／`multi` 的 `options` 由引擎洗牌並重算 `answer`，題庫不必自己洗；干擾項要「看起來合理」（對應常見錯誤做法），不可明顯離譜，且彼此不同、與正解不同。
- `multi` 至少 2 個正解、至少 1 個錯項；題幹需明示「選出所有正確的」。
- `tf` 題幹是一個陳述句；陷阱題的陳述要「看似對實則錯」或相反。
- `calc`：題幹是純算式或算式敘述，作答只批改最後答案；`explain` 要寫出列式與步驟。
- `word`：應用題，題幹含情境，答案可含單位；`units` 要列齊常見單位。
- 答案字串用引擎規範化比對：全形轉半形、去空白與千分位逗號、去 `units`、分數與小數數值等價（`3/4`＝`0.75`＝`.75`）、帶分數寫成 `1 1/2` 亦接受。題庫仍應在 `accepted` 補上明顯的替代寫法（如 `2×3×3`、`2*3*3`）。
- 數值需「乾淨」：避免循環小數、避免答案超過 4 位小數；禁止產生答案為 0 或負數（除非題目本意）。
- 所有題目必須能由 `gen` 在 200 次連續呼叫中不丟錯、`explain` 非空、`options` 無重複。

## 3. 題庫量化門檻（每個 topic）

- 六種題型各 ≥ 5 個 spec，`level` 1～5 都要有覆蓋（每型至少涵蓋 3 個不同 level，整個 topic 涵蓋 1～5 全部）。
- 整個 topic：`trap` ≥ 8 個、`extend` ≥ 6 個，且 trap 至少分布在 4 種題型以上。
- `extend` 題＝跨概念、逆向思考、多步驟或變形（如：已知結果反求條件、兩個概念合用）。
- 題幹必須對應該 topic 的教學內容，用台灣用語（公分、公升、元、時速…），禁簡體詞。
- 不得抄襲出版社原題；全部自編。

1. 顯示目前版本（含切換翰林／康軒／南一的小選單）。
2. **單元可複選**：依六上／六下分組的核取方塊，附「全選／全不選／只選六上／只選六下」；至少選 1 個才能開始。
3. **題型可複選**：六種題型各一個核取方塊，預設全選，至少選 1 種。
4. **難度範圍**（加分項）：預設「簡單→深入（全部）」。
5. **考卷模式二選一**：
   - 📄 **一百分計分卷**：整份交卷後一次批改、顯示總分（滿分 100）。
   - ✏️ **二十題逐題練習**：共 20 題，每題作答後可立即「檢查」並看解析，最後顯示統計。
6. 「開始出題」按鈕。選擇用 `localStorage`（鍵名 `meihao-exam:grade6-math:<version>`）記住，讀不到就用預設，不得因為 storage 失敗而壞掉（try/catch）。

## 7. 組卷規則（engine.js，需有單元測試）

共同：
- 候選池＝所選單元對應 topics 的 spec，再依所選題型與難度範圍過濾。
- 單元均衡：選多個單元時，各 topic 被抽到的題數差距 ≤ 1（池夠的話）。
- **由簡入深**：題目排序先依 `level` 升冪（同 level 內隨機）；整份卷 `level` 分布盡量涵蓋所選範圍。
- **包含易錯陷阱與延伸**：池夠時，`trap` 題數約占 20%（至少 2 題）、`extend` 約占 20%（至少 2 題）；其餘 `basic`。`extend` 偏排在後段（level ≥ 4），`trap` 分散在中段。
- 同卷不重複：同一 spec id 不重複出；池不足時才允許同 spec 再 gen 一次（變數不同）並在 console.warn。
- 每次「重新出題」都重新抽 spec 並重新 gen。

**一百分卷**（題數與配分，預設全選六型）：

| 題型 | 題數 | 每題分 | 小計 |
|---|---|---|---|
| single 單選 | 8 | 3 | 24 |
| multi 複選（全對才給分，不倒扣） | 3 | 5 | 15 |
| tf 是非 | 5 | 2 | 10 |
| fill 填空 | 6 | 3 | 18 |
| calc 算式題 | 4 | 4 | 16 |
| word 應用題 | 3 | 6/6/5 | 17 |

若使用者只勾部分題型：以上表各型「小計」為權重，等比例分配 100 分，用最大餘數法讓總分剛好 100；題數按各型預設題數等比例縮放（每型至少 2 題，除非池不足）。卷內版面順序：按題型分大題（一、單選 二、複選…），大題內由簡入深；大題標題顯示題數與配分。

**二十題逐題練習**：總共 20 題，所選題型平均分配（餘數給靠前的題型），**整體由簡入深**（第 1 題最易、第 20 題最深）。每題 5 分、可在題旁看「基礎／易錯陷阱／延伸」徽章（作答前只顯示 🔰基礎／⚠️易錯／🚀延伸 標籤，不洩漏答案）。每題有「檢查」鈕：立即顯示對錯＋解析＋（若為 trap）易錯點說明；全部作答完顯示統計。

## 11. 數字風格豐富度（2026-10-11 使用者追加：變數不夠豐富，沒用到分數、整數、小數）

問題：舊題庫約 8 成題幹只有整數，圓題的「小數」只是 π＝3.14 的字樣。要求同一個題型能用「整數／小數／分數／帶分數」各種數字命題，且位數規模多樣（個位到三四位數、0.5 到 12.75、1/2 到 3 5/8）。

工具（`exam-engine/kit.js` 已追加，介面固定）：`kit.Q(n,d)` 有理數；`qAdd/qSub/qMul/qDiv/qCmp/qVal/qIsInt/qIsTerminating`；顯示 `qFrac`（假分數）、`qMixed`（帶分數 `1 3/4`）、`qDec`（有限小數，無限回 null）、`qShow(q,flavor)`；`kit.flavor(allowed, weights)` 抽風格；`kit.randQ(flavor,{min,max,dens,places})` 產生指定風格的數；`kit.qAnswer(q,flavor)` 回 `{answer, accepted}`（其餘等價寫法自動放 accepted）。風格 key：`int`、`dec`、`frac`、`mixed`。
做法：gen 開頭抽 flavor → 用 `randQ` 取數 → **全部用 Q 做精確運算**（不要用浮點）→ 題幹用 `qShow` 顯示 → 答案用 `qAnswer`。同一道題的數字風格要能在多次 gen 之間變化（例如圓面積題：半徑 6、2.5、3 1/2 公分；速率題：時速 54、4.5、3 3/4 公里）。

規則：
1. 凡是 calc／fill／word 型 spec，且題目本質允許，必須能在多次 gen 中出現至少 2 種風格（`verify-numbers.js` 檢查：每 topic ≥60% 的這類 spec 為多風格）。
2. 每個 topic（除下述豁免）題幹中：含小數 ≥25%、含分數或帶分數 ≥25%、純整數 ≥20%（`verify-numbers.js` 統計；圓周率 3.14／22/7 字樣不計入）。位數規模至少涵蓋 2 種以上（factor 至少 3 種）。
3. 豁免：`factor` 本質整數，只要求位數規模豐富（例如 2～3 位數、含較大的數）；`fraction-div` 不要求純整數題（但要有小數風格＝小數與分數混算、化互）；`decimal` 不要求純整數與分數。
4. 圓題（circle-length／circle-area／solids 的圓柱）：半徑或直徑要有小數與分數風格；題幹寫「圓周率取 3.14」或「取 22/7」（22/7 只搭配半徑為 7 的倍數的整數或分數題，確保算得乾淨）。
5. 答案仍須乾淨：有限小數或最簡分數；不得出現無限循環小數當標準答案（遇到就改數字或要求「以分數表示」）。答案若是分數風格，`accepted` 必含等價小數（若為有限小數）與帶分數寫法；若是小數風格則 accepted 含最簡分數。
6. 干擾選項要與題幹風格一致（分數題的選項用分數，小數題用小數），並對應真實誤算。
7. 修改既有 spec 不得降低原有正確性：改完要重跑 `verify-banks.js`，並自寫獨立重算腳本（用不同於 gen 的算法，從題幹解析數字）抽驗各 topic 數百題；答案錯誤是最重缺陷。
8. 不得改 spec id（錯題統計用）；可新增 spec，但仍須維持第 3 節量化門檻。

驗收指令（在 `dist/courses/grade6-math`）：`node verify-banks.js`、`node verify-numbers.js` 皆 ALL PASS。

## 12. 依教材慣用寫法編題（2026-10-11 使用者定案，鎖定）

- **未知數一律用框「□」，不得改成 x、X、y 等字母**（教材用框，孩子才不會不習慣）。同一題有兩個以上未知數時依序用 □、△、○。例：`3:□ = 27:21`、`□ × 0.6 − 3/5 = 2.4`。
- 一般性敘述（如分配律、運算規則）不用 a、b、c 之類字母，改用具體數字舉例，或用「某數」「甲、乙」等文字，或用 □、△。
- 圓的半徑、直徑、圓周率等一律寫中文（半徑、直徑、圓周率），不用 r、R、d、π 以外的字母；圓周率寫「圓周率取 3.14」。
- 乘號用「×」、除號用「÷」，不得用字母 x 或星號 *；比用「:」。
- 單位用中文（公分、公尺、公升、平方公分），不用 cm、m、L 等英文縮寫。
- `verify-banks.js` 與 `verify-numbers.js` 之外，另以 `node verify-notation.js` 檢查：學生可見文字（題幹、選項、解析、易錯點）中不得出現獨立的英文字母（π 除外）。
- 日後國語／社會／自然比照：用字遵循該科教材慣用寫法，不自創符號。

## 13. 兩種模式的定位與難度（2026-10-11 使用者定案，鎖定）

- ✏️ **二十題逐題練習＝「加強練習」**：只依所勾選的題型出 20 題；固定由簡入深（level 1→5 全範圍），**不套用難度選擇**（首頁選擇難度時此模式忽略，並在畫面上註明「二十題練習由簡入深，不受難度影響」）。
- 📄 **一百分計分卷＝「一般考卷」**：**依所選難易度出題**，分四檔：簡單（基礎暖身）、中等、困難（挑戰深入）、綜合（簡單→深入）。難度選單只在選擇一百分卷時顯示或啟用。各檔的 level 範圍沿用 config.levelRanges；題目按 level 由簡入深排序；易錯陷阱與延伸題的配額依該檔可用題數調整（簡單檔不強求延伸題，困難檔延伸題比例提高到約 30%；池不足時降級但不報錯）。

## 14. 教材 □ 未知數題型（2026-10-11 使用者指示：根據出題模式加題）

每個 topic 要新增含 □ 的 spec（factor 至少 4 個，其他 topic 至少 8 個），涵蓋 level 1～5 至少 4 級，且分布在 calc／fill／single／word／tf 中至少 3 種題型；`verify-notation.js` 會檢查。典型寫法（教材式）：`□ × 3/4 = 12`、`3.6 ÷ □ = 0.9`、`(□ − 3) × 10 = 30`、`3:□ = 12:20`、反求半徑／邊長／時間／基準量，以及 □、△ 兩個未知數的題（如 `□ + △ = 10，□ − △ = 2`）。含 □ 的題也要有易錯陷阱（如把 □ 移項方向弄反）與延伸（逆向、多步）。新增 spec 的 id 須唯一，仍遵守第 3、11、12 節所有規則。
